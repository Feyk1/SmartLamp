# Dashboard and Simulation Panel

**vanilla JS** web application (no npm build). The backend serves the APIs and
the WebSocket; `web/` only contains static HTML, CSS and JS.

## Structure

| File | Purpose |
| :--- | :--- |
| `index.html` | User dashboard |
| `sim.html` | Simulation Panel |
| `src/app.js` | Dashboard logic |
| `src/sim.js` | Simulation Panel logic |
| `src/i18n.js` | ES/EN texts (English by default) |
| `src/endpoint.js` | Resolves the backend/WS for local, LAN and Fly |
| `src/help.js` | Shared help dialogs |
| `src/assistant.js` | Rule-based, client-side assistant |
| `src/assistant-knowledge.js` | Generated from `docs/manual/` |
| `src/styles.css` | Dashboard styles |
| `src/sim.css` | Simulation Panel styles |
| `config.js` | `window.LAMP_CONFIG` (generated by the entrypoint) |
| `server.py` | Local static server (`:3000`, no cache) |
| `build_site.sh` | Builds the site for GitHub Pages |
| `Dockerfile.dev` | Development image for the `web` service |

## Development

```bash
# From the repository root
docker compose up --build web backend

# Dashboard:  http://localhost:3000
# Sim Panel:  http://localhost:3000/sim.html?pin=2025
```

To serve the static files without Docker (with `config.js` pointing to
`http://localhost:8080`):

```bash
python3 web/server.py
```

The dashboard obtains an ephemeral ticket for the WebSocket
(`POST /instances/{id}/ws-ticket`); the JWT does not travel in the WS URL.
